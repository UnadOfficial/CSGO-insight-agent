## CI/CD 流水线补全（GitHub Actions）

分析项目架构后改造/新增工作流，补齐缺失的「部署」环节：

- `.github/workflows/ci.yml`（改造）：新增 `rust-tools` job 检查 `tools/demo-cosmetic-rewriter`（此前完全未被 CI 覆盖，release workflow 却缓存了它的 workspace）；frontend job 增加 `frontend/dist` 产物上传；新增 `ci-gate` 汇总 job 供分支保护单点勾选；版本/工具链常量提到 workflow 级 `env`。
- `.github/workflows/release-windows.yml`（改造）：`release` job 增加 `outputs.version`（Resolve release version 步骤加 `id: version` 并写 GITHUB_OUTPUT）；新增 `deploy` job（ubuntu，environment=production）——下载安装包产物 → `pnpm run deploy:r2` 推 NSIS 安装包 + `latest.json`/`latest.yml` 到 Cloudflare R2 → 轮询校验 manifest。新增 `update_mode`、`deploy` 两个 dispatch 入参。
- `.github/workflows/deploy-cloudflare-worker.yml`（新增）+ `infra/cloudflare/wrangler.toml`（新增）：部署 `update-proxy-worker.js`。
- `docs/ci-cd.md`（新增）：架构速览、三条流水线、Secrets/Variables 清单、分支保护、发版步骤、故障排查。

关键约定：
- 依赖边界分离：Python `uv.lock` / 前端 `frontend/pnpm-lock.yaml` / Rust 各自 `Cargo.lock`，CI 一律 `--frozen` / `--frozen-lockfile` / `--locked`。
- 平台约束：后端与前端测试必须跑 `windows-latest`（录制/OBS/CS:GO 控制台注入仅 Windows）；纯 Rust 工具跑 ubuntu。
- R2 / Cloudflare 凭据缺失时 deploy 只告警跳过，不阻断发布（保留原有「发版不依赖 R2」的行为）。
- upload-artifact 多路径时 LCA 为仓库根，download 后路径结构保持不变，正好对齐 `deploy-r2.mjs` 里写死的 `src-tauri/target/release/bundle/nsis`。

### 追加：用户确认不需要 Cloudflare R2

- R2 是纯分发通道，三个 R2 secret 缺失时 deploy job 只 warning 跳过，**构建/签名/GitHub Release 照常**，流水线仍绿。
- 真正的坑是 `TAURI_SIGNING_PRIVATE_KEY`：`frontend/src-tauri/tauri.conf.json` 里 `plugins.updater.pubkey` 已填 + `bundle.createUpdaterArtifacts: true`，构建缺私钥会硬报错
  `A public key has been found, but no private key. Make sure to set TAURI_SIGNING_PRIVATE_KEY environment variable.`
  → 已在 release-windows.yml 打包前新增 `Verify updater signing configuration` 步骤，提前明确报错。
- 彻底去掉自动更新的做法：`createUpdaterArtifacts: false` + 删除 `plugins.updater` 整段；Cargo 的 `tauri-plugin-updater` 与 `src-tauri/src/lib.rs` 注册不用动（删配置不编译失败）；前端 `frontend/src/utils/shouldCheckAppUpdates.js` 会跳过检查（`endpoints` 本就是空数组）。
